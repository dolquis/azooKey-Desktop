# 状態語の語彙と書き換え例

`scripts/docs-lint.py` の `status` カテゴリが検出する語彙と同じもの。README / `docs/` / `plans/` に書く前に、この語が要らないか確認する（`docs/linear-conventions.md` と `docs/archive/` は対象外 — 前者は状態運用そのものが主題、後者は完了した記録）。

## 検出される語

現状・現時点・実装済み・未実装・対応済み・着手済み・着手前・暫定・当面・現行・未定・未確定・未検証・残作業・残課題・完了後・完了済み・完了している・完了しました・待ち）・待ちである・TODO・FIXME・既知の未確定

## 書き換えパターン

| 状態語を含む例 | 定義文への書き換え |
|---|---|
| 「現状 `ZenzaiModelConverter` は gguf を probe するのみ」 | 「`ZenzaiModelConverter` は GGUF 指定時のみ実推論を行う。未指定時は SimpleConverter へフォールバックする」 |
| 「`azookey_settings.exe` は未実装（M11/M30）」 | 実装済みなら削除。未実装が事実なら「M11/M30 が `azookey_settings.exe` を実装する」 |
| 「暫定的に `--typo-mode` を使う」 | 採用するなら状態語なしで仕様として確定。採用しないなら記述ごと削除 |
| 「M46 完了後に配線する」 | 「M46 の PrivacyGate が利用可能なときのみ判定する」（機能条件。時系列ではない） |
| 「DEV-223 は中止された」 | Linear へ。repo docs には経緯を残さず、確定した仕様だけを書く |
| 「157件中156 passed」のような実測件数 | 削除。CTest の結果は実行するたびに変わり、docs は追随できない |
| 行番号付きコード参照（`Foo.cpp:123`） | 関数名・クラス名までに留める。行番号はリファクタで即座に陳腐化する |

## 許容される例外

- 依存関係としての「M46 完了」（roadmap の「前提」欄など、milestone の依存グラフを表す場合）はこの検査の対象外になりうるが、疑わしい場合は機能条件の文へ書き換える方が安全。
- チェックリスト文書（`docs/handoff/*.md` の一部）で「☐ 既知(DEV-xxx)」のように中立的な追跡リンクとして DEV 番号を使うのは許容する。「DEV-xxx が Done」のような状態記述にしない。
- 意図的な誤検知は `<!-- lint:allow status -->` をその行または直前行に置いて免除する。多用しない — 免除が増えるほど検査の意味が薄れる。
