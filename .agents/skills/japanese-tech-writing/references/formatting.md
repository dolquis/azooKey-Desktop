# Markdownと表記

Markdownの構造、用語の示し方、コード断片の配置を直す場合に読む。

## 改行とブロック

- 一文ごとに改行し、段落は空行で分ける。
- コード、差分、ログ、設定ファイルの断片はコードブロックで示す。
- 本筋から一段外れる由来や補足は、本文の流れを止める場合だけ脚注（`[^ラベル]`）へ移す。
- 定義や分類は箇条書きにできる。初出の定義語は太字、導入後の言及、引用、通称は「」を使う。

## 記号

- 日本語の地の文や見出しでemダッシュ、horizontal bar、二倍ダッシュを区切り記号として使わない。補足は括弧、言い換えは二文または読点で表す。
- 日本語の並列に中黒を使わない。単一の固有名詞の内部は例外とする。
- 用語と定義の列挙は「**用語**：説明」とし、ダッシュを区切りに使わない。
- コード、書誌情報、範囲を示すenダッシュ、英語の複合語は上記の対象外とする。

## 見出し

- 見出しは、その節が扱う対象または問いを特定できる自然な句にする。
- 「基礎」「補足」「例に戻す」のように内容を特定しない見出しを避ける。
- 見出しへ種別と主題を区切り線で詰め込まず、要素を絞るか助詞でつなぐ。
- 節の結論を決め台詞として先に言い切る見出しは避ける。

## 技術要素

- ファイル名、関数名、設定キー、コマンドは実体と照合する。
- 変動する行番号やテスト件数は、恒常文書の契約に必要な場合を除いて固定しない。
- 引用、既存の識別子、コード内の表記は、文章上の好みだけで変更しない。
