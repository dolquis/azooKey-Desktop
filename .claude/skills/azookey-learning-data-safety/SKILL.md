# azooKey 学習データ安全性

学習機能の変更を、入力取得からメモリ保持、永続化、再読込、削除まで一続きのデータライフサイクルとして扱う。

## 手順

1. `references/spec-routing.md` を読み、変更対象に対応する仕様、実装、テストを特定する。
2. 入力、メモリ、永続化、import/export、ログ、削除、migration のどこを通るかを列挙する。
3. `.codegraph/` があり CodeGraph が利用可能なら関連モジュールと呼び出し経路を確認する。Serena が利用可能なら active project と languages を確認してから対象シンボルと参照元を確認する。利用できない場合は `rg` と実ファイルで同じ範囲を確認する。
4. 既存の atomic write、file lock、quarantine、fallback の契約を保つ最小差分にする。
5. 対象テストを先に実行し、必要に応じて `azookey_check` まで広げる。
6. 永続化形式、ユーザー可視挙動、責務境界が変わる場合は対応する仕様文書を同じ変更で更新する。

## 必須ガードレール

- secure input 中は学習、永続化、外部送信、平文ログ出力を行わない。
- ユーザーデータをリポジトリ、テスト成果物、MSIX、診断ログへ混入させない。
- 複数プロセスが触る永続化は atomic replace と lock の既存設計を崩さない。
- 旧形式や破損ファイルを無言で初期化または破棄しない。検出、隔離、復旧、通知の既存契約を確認する。
- 削除や上書きでは対象パス、影響範囲、回復手段を明示する。
- `legacy/` は参考資料に留め、Windows 版の正典として扱わない。

## 完了条件

- 正常系に加え、並行更新、破損データ、旧バージョン、secure input の該当ケースを検証する。
- 実行したテスト、実行できなかったテスト、残るデータ安全性リスクを報告する。
- 実機でしか確認できない項目は自動検証成功と混同せず、人間ゲートとして分離する。
