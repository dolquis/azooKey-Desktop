# ドキュメントガバナンス

repo docs は「今どうなっているか」の実況ではなく「何が正しいか」の定義を保つ契約書として扱う。実況を書くと、実装が追いつくたびに無言で嘘になる。

状態・進捗・優先度の正典は Linear にある。repo docs にその状態を書いた瞬間、無効化機構のない手書きキャッシュができ、元データが動くたびにずれる。読み手は書かれた日付を知らないので、嘘だと気づけない。

## 最初に確認すること

1. この情報の正典はどこか。判断できないときは [placement.md](references/placement.md) を読む。正典でない場所に書くなら、リンクと 1〜2 行の案内に留める。
2. repo に正典マトリクス（何がどこの正典かの表）が AGENTS.md にあるか。無ければ、作るのが最初の作業になる。雛形は placement.md にある。
3. 触る文書は生きた定義か、凍結された記録か。決定ログ・監査記録・アーカイブは日付つきの過去記録なので、状態語を含んでいても直さない。

## 見出しは状態を主張しない

本文は状態を記録してよい。日付を伴えば過去の事実として読まれるからである。見出しは違う。見出しは文書の骨格で、読み手が拾い読みする対象で、日付を添える余地がない。

- `## 0. 現状サマリ（2026-06-09 時点）` は翌日から嘘になり、読み手には判別できない。
- `### P1-1. オンボーディング ✅ 完了 (PR #7)` は Linear が持つべき状態を見出しに固定している。
- `### P3-6. 開発環境ハードニング（未着手）` も同じ。着手した日に嘘になる。

見出しから状態を外し、定義文へ言い換える。`（未着手）` は削除、`✅ 完了 (PR #7)` は削除して Linear の Done を正とする。書き換えの型は [rewrite.md](references/rewrite.md) にある。

完了マーカーを消す前に、その完了が Linear に Done として存在するか確かめる。roadmap が唯一のトラッカーだった期間があるなら、削除ではなく日付つきで `docs/archive/` へ移す。記録を失うのは陳腐化より重い。

## 検査を回す

`python3 scripts/docs-lint.py` を実行する。結果は 2 ティアに分かれる。

- **DECISIVE** は実在しない参照と、状態を主張する見出しである。ヒットは本物なので、その場で直す。
- **HEURISTIC** は文中の状態語で、過検出を前提にファイルごとの件数だけが出る。件数をゼロにするのは目的ではない。件数の多いファイルは、たいてい生きた定義ではなく凍結すべき記録である。

運用（設定ファイル、免除コメント、ベースライン、CI への載せ方）は [docs-lint.md](references/docs-lint.md) を読む。状態語の語彙は列挙せず、`--print-words` で得る。語彙をどこかに書き写すと、それ自体が次の手書きキャッシュになる。

## 検査が見ていないところ

見出しを締めると、状態は逃げ場を探す。次は機械では追っていないので、人が見る。

- 表の「状態」「ステータス」「進捗」列。`| 機能 | 実装済み |` は見出しと同じ実況である。ただし状態の意味を定義する表（`| ステータス | 意味 |`）は正しい用法なので混同しない。
- frontmatter の `status:`、チェックリストの `- [x]`、絵文字の凡例。
- コード参照の行番号と実測件数。ファイル名・関数名までに留める。行番号はリファクタで即座に陳腐化する。

## 実装 PR での責任

機能を実装したら、その変更が偽にした spec の記述を消すところまでが同じ PR の範囲である。spec が実装に追いつかないのは、たいてい「実装 PR は docs を更新しなくてもマージできる」からで、そこを止めるのがこのスキルの役目になる。

PR 本文の Documentation impact 欄に、更新した文書と、更新しなかった理由を書く。

## 文書を追加・移動するとき

置き場所と索引の規則は placement.md にある。要点は 2 つ。

- 一回限りの引き継ぎ文書は DoD 達成後に `docs/archive/` へ移す。恒常的に使う手順は残し、索引に載せる。
- ある文書が別の文書を「正典」と宣言したら、参照される側にも「本節は X から参照される」の 1 行を置く。片方向の宣言は参照先の変更に追随しない。

## 迷ったときの原則

同じ内容を 2 箇所目に書きたくなったら、1 箇所目へのリンクにする。状態を書きたくなったら、それが Linear から導出できないか確かめる。導出できるなら書かない。
