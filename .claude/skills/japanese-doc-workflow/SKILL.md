# Japanese Doc Workflow

日本語技術文書の目的と変更内容から、必要な文章規範を選択する入口として使う。

## Skill の選択

- 表記、文体、冗長さを直す場合は `japanese-tech-writing` を読む。同Skillが案内するreferenceは作業に必要なものだけを読む。
- 段落間の飛躍、論証の無理、A-B-Aの割り込み、理論や引用の空転を直す場合は `argument-gap-edit` を読む。
- 新規文書を共同設計する場合、Claude Codeでは `doc-coauthoring` を併用できる。CodexではClaude専用工程を省略し、目的と読者を確認してアウトラインを作る。
- 短いコメント、コミットメッセージ、軽い箇条書き、コードだけの変更では、このワークフローを広げない。

複数のSkillが必要な場合も、用途を決めてから順番に読む。全Skillの無条件な読み込みは行わない。

## 守ること

- 既存文書を編集するときは、事実関係、用語、既存の文体を勝手に変えない。
- 根拠のない断定、架空の引用、未確認の仕様説明を追加しない。確認できないことは確認できないと書く。
- 大きく書き換える前に、レビューのみ、差分修正、全面リライトのどれを行うかを決め、必要なら依頼者へ確認する。

## 作業手順

1. 文書の目的、読者、公開先、完成形、変更範囲を確認する。
2. 新規作成ではアウトラインを作り、既存文書では事実と用語を保った差分修正を基本にする。
3. 上の基準から必要なSkillとreferenceを選ぶ。
4. 構成を直してから文体と表記を整える。
5. repositoryにtextlint設定と実行環境がある場合はlintを実行する。導入だけを目的に依存関係を追加しない。
6. lint警告は文脈に照らして採否を判断し、最終差分で事実、論理、表記を確認する。
7. 報告は変更内容と未確認事項に絞り、固定の分類見出しを小さな修正へ強制しない。
