# 段落と論証

段落の順序、因果、反論、説明の飛躍を直す場合に読む。

## 段落の役割

- 一つの段落には一つのトピックを置く。調査、報告、検証、評価が混ざる場合は論理の一歩ごとに分ける。
- 冒頭の文で段落の役割を示し、前段落から何を受け、次へ何を渡すか確認する。
- 新しい例や抽象語を導入するときは、前の例との違いと必要性を先に示す。
- 前方参照は論証が一区切りした段落末または節末に置き、参照先で回収する。

## 主張と根拠

- 因果を述べる場合は、その機構を一文で示す。悪い例：「手順で分けると変更が全体に波及する」。良い例：「各工程がデータを受け渡すための表現を共有してしまい、その表現を変えると全体に波及する」。
- 例が主張の一部しか支えない場合は、主張を例が支える範囲まで狭める。
- 複数の要因を単一原因へ還元せず、各要因と説明手段を対応付ける。悪い例：契約の不在と情報隠蔽の失敗が混ざった事故を、丸ごと「情報隠蔽の問題」と説明する。
- 異なる決定、原因、問題を「同じ」とまとめない。悪い例：相互依存する三つの未決事項を「同じ決定を別々に下していた」と書く。良い例：「どれも別々の決定であり、しかも互いに依存している」と分ける。上位語でまとめる場合は共通点を先に説明する。
- 検出、保証、解決の条件を明示し、例だけを根拠に無条件の「必ず」へ広げない。

## 反論と不確実性

- 反論と疑念を処理してから結論を一度だけ置く。結論、反論、同じ結論の順に往復しない。
- 「AではなくB」と否定するときは、Aを否定する根拠または反実仮想を添える。
- 誤解されそうな命題は具体的に書き出して否定し、漠然と「すべてが解決するわけではない」で済ませない。
- 譲歩では確認できる事実だけを認め、後で訂正する因果を著者自身の断定として置かない。
- 推量、可能性、読者の疑念、反実仮想を表す弱い述語は保持する。本文の根拠が命題を確定するときだけ断定に直す。悪い例：「提示し続けているかもしれない」を「提示し続けている」に変える。良い例：「提示し続けている可能性がある」のように、不確実性を残して文を整える。
- 逆接や限定を置いた段落は、その後で議論を進め、宙吊りにしない。

## 読者の負荷

- 後で参照しない固有名や数値を増やさない。判断に必要な具体は残す。
- 抽象的な指示語が一意に決まらない場合は、括弧または短い言い換えで対象を特定する。
- 節の中心語は、対象範囲と意味を定義してから使う。
- 章や節をまたぐ用語、分類、責務の地位を揃える。
- 山場で効かせたい情報（数値、固有の事実）は、その手前の段落で先出ししない。

## 読者への誠実さ

- 確認していない事実を確認済みのように書かない。
- 作為的に見える例には、現実に起こりうる根拠を短く添える。著者の自信だけを根拠にしない。
- 引用や理論は、その後の判断または説明を変える場合だけ残す。知識紹介で流れを止める場合は脚注、コラム、削除を検討する。
