# 決定記録と測定記録（`docs/decisions/`）

本ディレクトリは、日付つきの決定記録と測定記録を置く場所である。
spec と roadmap は結論と条件だけを持ち、決定の経緯、根拠となった観測、実測値はここに置く。
状態と進捗の正典は Linear であり、本ディレクトリは持たない。

## 何を書くか

| 種別 | 内容 | 例 |
|---|---|---|
| 決定記録 | ある時点で選んだ方針、比べた候補、根拠、不採用の理由、再評価の条件 | 署名経路の選定、PCH の不採用 |
| 測定記録 | 固定した条件での実測値、測定手順、測定の限界 | NLL の Release 測定、R1 CPU baseline |

日付、DEV 番号、PR 番号、commit、実測値、「確定」などの状態語を書いてよい。
docs-lint は `**/decisions/**` を prose 検査（状態語・見出しの状態表記・行番号参照）と索引検査の対象から外している。
リンク検査は効くので、相対リンクは実在するファイルを指す。

ここに置かないもの:

- 現在も守る契約（データ構造、設定キー、fallback、手順）。対応する spec か runbook に置く。
- 進捗、担当、次にやること。Linear に置く。

## ファイル名

`YYYY-MM-DD-<slug>.md` とする。

- 日付は、本文に記録された決定日または測定日である。記録を書いた日や移設した日ではない。
- 原記録が年月までしか持たない場合は `YYYY-MM-<slug>.md` とする。
- 原記録が日付を持たない場合は、所有 Issue（Linear）から決定日を引く。
  引けない場合は、関連する最も早い日付を使い、ヘッダにその根拠を書く。
- `<slug>` は主題を表す英小文字とハイフンの語にする。DEV 番号は slug に入れない。

## 書式

冒頭に次の固定項目を置く。

```markdown
# <主題>

- 種別: 決定記録 | 測定記録
- 日付: <決定日・測定日。年月までなら年月>
- 関連 Issue: <DEV-xxx。無ければ「なし」>
- 結論の正典: <spec のパスと §。spec 側からも本ファイルへリンクする>
- 移設元: <移設した場合、元のパスと §、移設時点の commit>
```

本文は移設元の原文をそのまま置く。
要約や書き換えをした場合は、ヘッダの「移設元」に元の commit を書き、原文を git 履歴で辿れるようにする。
原文中の `§` 参照は移設元の文書の節を指す。必要なら本文の前に 1 行で補う。
原文に含まれる結論と条件は spec と重複してよい。正典は spec であり、本ディレクトリの原文は移設時点のスナップショットである。

## 追記のみで書き換えない

記録は凍結する。
後から事実が変わっても既存ファイルの本文は直さず、新しい日付で別のファイルを作る。
既存ファイルに足してよいのは、末尾の「後続」節に新しいファイルへのリンクを 1 行置くことだけである。
誤記の訂正が必要なときも、訂正を新しいファイルに書き、元のファイルからは「後続」でリンクする。

## spec からの参照

- spec の節には、結論と条件（再評価の条件を含む）を残し、経緯と実測は本ディレクトリの該当ファイルへ 1 行でリンクする。
  `docs/` 直下の spec からは `[decisions/<file>.md](decisions/<file>.md)` の相対リンクで書く。
  例: [`neural-reranker-spec.md`](../neural-reranker-spec.md) §B12 から [`2026-09-08-nll-release-measurement.md`](2026-09-08-nll-release-measurement.md) へのリンク。
- spec の § 番号と見出しは残す。節の中身をすべて移す場合も、見出しの下に結論とリンクを残す。
- 正典宣言は双方向にする。spec がファイルへリンクし、ファイルはヘッダの「結論の正典」で spec の § を指す。
- 本ディレクトリのファイルを、現在の契約の根拠として spec の代わりに引用しない。契約は spec を引く。
